# MateView Guardian v0.2 GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship self-contained macOS ARM64 and Windows x64 tray applications that block the MateView touch strip, preserve normal system volume controls, and maintain a configurable internal speaker volume.

**Architecture:** A shared .NET 10 core owns settings, state derivation, correction decisions, and a serialized watchdog. An Avalonia 12.1.1 desktop app supplies the settings window and native tray menu, while platform adapters isolate macOS `hidutil`/AppleSiliconDDC processes from Windows PnP elevation and `Dxva2.dll` calls.

**Tech Stack:** C# 14, .NET 10, Avalonia 12.1.1, xUnit, PowerShell 5.1-compatible HID helper, POSIX shell, AppleSiliconDDC pinned at `67ff964ab8123d9d35fadf7d8e1a7c677d31da14`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-03-v0.2-gui-design.md`

## Global Constraints

- Supported display identity is `ZQE-CAA`; USB identity is VID `0x12D1`, PID `0x10B6`.
- Default target volume is `30`; accepted range is `0...100`.
- The active DDC interval is 500 ms; unavailable-device backoff is capped at 10 seconds.
- DDC calls are serialized and may write only VCP `0x62` and, on Windows, `0x8D = 2`.
- Windows HID mutation accepts only instance IDs beginning `HID\\VID_12D1&PID_10B6` and requires elevation.
- No telemetry, update service, global keyboard hook, filter driver, VCP `0xCA`, brightness, contrast, input, or power write is allowed.
- Existing v0.1 command-line packages and tests remain functional.
